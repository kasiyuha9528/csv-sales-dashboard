## Step 1:雛形作成、README・学習ノート

### やったこと
- `create-next-app` でNext.jsのプロジェクトを作成した(TypeScript、ESLint、Tailwind CSS、App Router、`src/` なし)
- `npm run dev` で、`http://localhost:3000` に初期画面が表示されることを確認した
- プロジェクトのフォルダで `git init` を実行した
- portfolio-template からREADME・学習ノート・LICENSEを作成した

### 学んだこと
- インストールされたバージョンは、Next.js 16.4.6、React 19.3.0、Tailwind CSS 4.3.3だった
- Next.js 16では、全リクエストの前処理を行うファイルの名前が `proxy.ts` になる(15以前は `middleware.ts`)。Step 3のログイン確認で使う
- Gitは、今いるフォルダに `.git` がないと親フォルダをさかのぼって探し、一番近い `.git` を使う

### つまずいた点と解決方法
- **症状**:プロジェクトのフォルダで `git status` を実行すると、`../Documents/` や `../NTUSER.DAT` などホームフォルダのファイルが一覧に出て、「Permission denied」の警告も大量に出た
- **原因**:プロジェクトに `.git` がなく、親の `C:\Users\User` に以前誤って作られた `.git` があった。そのため、ホームフォルダ全体が1つのリポジトリとして扱われていた
- **解決**:プロジェクトのフォルダで `git init` を実行し、専用のリポジトリを作って切り離した。この状態で `git add .` をしていたら、PC内の設定ファイルまでGitに入るところだった。作業前に `git status` で対象のファイルを確認する

## Step 2:Supabaseのテーブル・インデックス・RLSの作成

### やったこと
- Supabaseのプロジェクトを作成した(リージョンは東京)
- 作成時のセキュリティ設定は、「Enable Data API」をオン、「Automatically expose new tables」をオフ、「Enable automatic RLS」をオンにした
- SQL Editorで、`uploads`(取り込み1回分)と `sales`(明細)のテーブル、インデックス5つ、RLSのポリシーを作成した
- `@supabase/supabase-js` と `@supabase/ssr` をインストールした
- `.env.local` に接続先のURLとPublishable keyを設定し、`.env.example` に項目名だけを書いた

### 学んだこと
- RLS(行レベルセキュリティ)を有効にすると、ポリシーで許可した操作しかできなくなる。今回は「ログイン済み(`authenticated`)なら読み書きできる」ポリシーだけを付けたので、ログインしていない人(`anon`)はキーを知っていてもデータを扱えない
- 「Automatically expose new tables」をオフにすると、テーブルを操作する権限が自動では付かない。`grant` で、ログイン済みのロールにだけ権限を付けた。権限とRLSの二重で守る形になる
- Publishable keyはブラウザに出てもよいキーで、データはRLSで守る。Secret keyはRLSを無視できるので、ブラウザ側のコードや `.env.local` には入れない
- 古い形式のキー(anon / service_role)は2027年に廃止予定のため、新しい形式のPublishable keyを使った。環境変数名も `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` にした
- `check` 制約で、`status` に決めた3つ(pending / active / replaced)以外の値を入れられないようにできる
- `on delete cascade` を付けると、取り込み履歴(`uploads`)を消したときに、その明細(`sales`)もまとめて消える
- SQL Editorの「Run」で実行した時点で、データベースに反映される。「Save」はSQLの文章を残すだけ
- インストールしたバージョンは、`@supabase/supabase-js` 2.119.0、`@supabase/ssr` 0.12.7だった

### つまずいた点と解決方法
- **症状**:コミット前の確認で、`.env.example` の中身が空(0バイト)になっていた
- **原因**:ファイルを作成したあと、項目名を書いた内容が保存されていなかった
- **解決**:`NEXT_PUBLIC_SUPABASE_URL=` と `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=` の2行を書いて保存し直した。ファイルは作るだけでなく、中身が保存されているかも確認する

## Step 3:ログイン、ログアウト

### やったこと
- Supabaseの管理画面で、テスト用のユーザーを作成した(「Auto Confirm User」をオンにして、確認メールなしでログインできるようにした)
- Supabaseにつなぐ部品を、ブラウザ用(`lib/supabase/client.ts`)とサーバー用(`lib/supabase/server.ts`)に分けて作った
- `proxy.ts` で、リクエストのたびにログイン状態を確認し、未ログインなら `/login` へ、ログイン済みで `/login` を開いたら `/` へ移動させるようにした
- ログイン画面(`app/login/page.tsx`)とログアウトボタンを作った。エラーは要件定義書の文言で、原因別に表示する
- 確認用の仮のトップ画面を作り、ログイン中のメールアドレスと、`uploads` を読めたかどうかを表示した

### 学んだこと
- ログインの判定には `getClaims()` を使う。ログイン情報(トークン)の署名を検証してから返すため、偽のCookieを信用しない。`getSession()` はCookieの値を検証せずに返すので、サーバー側の判定に使ってはいけない
- `@supabase/ssr` は、ログイン情報をCookieに保存する。サーバー側でもログイン状態を読めるのはこのため
- `proxy.ts` では、Cookieを更新した `supabaseResponse` をそのまま返す必要がある。別のレスポンスを新しく作るとCookieの更新が失われ、勝手にログアウトされる原因になる
- Server ComponentではCookieを書き換えられないので、`server.ts` の `setAll` は失敗しても無視する。ログイン状態の更新は `proxy.ts` が担当している
- ログイン成功後は `router.replace("/")` で移動し、`router.refresh()` でサーバー側の表示も更新する。`replace` を使うと、ブラウザの「戻る」でログイン画面に戻らない
- ログインしていない人がAPIを直接呼ぶと、`42501`(permission denied)が返る。Step2で権限をログイン済みの人にだけ付けた効果を、curlで確認できた。エラーの `hint` には「anonに権限を付ける」方法が出るが、今回の設計では実行しない

### つまずいた点と解決方法
- **症状**:ログインすると「現在ご利用いただけません」と表示された。詳細は `AuthApiError: Invalid path specified in request URL` だった。続けてcurlで確認すると、`requested path is invalid` が返った
- **原因**:`.env.local` の `NEXT_PUBLIC_SUPABASE_URL` に、後ろに余計なパスが付いたURLを貼っていた。そのため、ログインの通信先が存在しないパスになっていた。curlでも、同じURLをもとにしたため `/rest/v1/` が二重になっていた
- **解決**:URLを `https://xxxxxxxx.supabase.co` の形(`.supabase.co` で終わる)に直し、`npm run dev` を再起動した。環境変数は起動時にだけ読み込まれるので、変更したら再起動が必要

## Step 4:突合用の正解データを作るスクリプト

### やったこと
- `scripts/make-expected.mjs` を作った。CSVを直接読み、月×カテゴリ×商品×担当者ごとの合計を計算して、`data/expected/` にJSONで書き出す
- 検証用のCSVを3つ `data/` に置いた。サンプル(1,000行)、10万行版、置き換えテスト用(サンプルの2026年10月分を修正したもの)
- 3つとも正解データを作り、サンプルの合計が2,518,378円になることを確認した
- 置き換えの範囲を「CSV内の一番早い日〜一番遅い日」(案B)のままにすると決めた

### 学んだこと
- 正解データは、アプリのコード(取り込み・集計RPC)とは別に作る。同じロジックを使うと、間違いも一緒にコピーされて突合の意味がなくなる
- 細かい単位(月×カテゴリ×商品×担当者)の合計で持っておけば、どんな絞り込み条件の正解も、あとから足し算で作れる
- 正解データに不正な行が混ざると突合の意味がないので、解釈できない行が1件でもあれば止めるようにした
- BOM付きUTF-8は、ファイルの先頭に3バイト(EF BB BF)が付く。Excelで保存したCSVによくある形式で、受け取ったサンプルもこの形式だった。UTF-8として読めないファイルは Shift_JIS として読む
- 日付は `new Date` に任せず、年・月・日が変わっていないかを確かめる。`2024-13-04` のような存在しない日付を、JavaScriptは翌年の日付に直してしまうため
- 置き換えテスト用のCSVは、範囲の端の行(10月2日・31日)を残して作った。案Bでは、端の日の行を消すと範囲が狭くなり、古いデータが残るため
- GitHubが警告を出すのは50MBを超えるファイル。10万行版(6.2MB)は、ほかの人も同じデータで確かめられるようにコミットした

## Step 5:CSVアップロード(読み込み・文字コード判定・検証・プレビュー)

### やったこと
- `lib/csv/parseSalesCsv.ts` を作った。CSVを読み込み、文字コードを判定し、1行ずつ検証して、取り込める形の行と、行数・期間・合計金額を返す
- `/upload` 画面を作った。ファイル選択(ドラッグ&ドロップ対応)→ 内容の確認、の流れで、エラーの行や金額不一致の警告を一覧で表示する
- 全画面で使うヘッダーを `app/components/AppHeader.tsx` にまとめ、今いる画面のメニューに色を付けた
- 3つのCSVで、行数・期間・合計金額がStep4の正解データと同じになることを画面で確認した。10万行版の読み込みは0.38秒だった
- 日付を壊したCSVで、エラーの一覧が出て取り込めないことを確認した

### 学んだこと
- CSVの区切りやダブルクォートの処理は、ライブラリ(Papa Parse)に任せた。正解データを作るStep4のスクリプトとは別の方法で読むことで、両方が同じ間違いをする危険を減らせる
- `TextDecoder("utf-8", { fatal: true })` で読めなければ Shift_JIS として読む、という順番で文字コードを判定した。BOMは `TextDecoder` が自動で取り除く
- 読み込みはブラウザの中だけで行い、この段階ではサーバーに何も送らない。エラーがあればファイル全体を止めるので、一部だけ取り込まれることがない
- 取り込めない行(エラー)と、取り込めるが確認してほしい行(警告)を分けた。数量×単価と金額が合わない行は、値引きなどの可能性があるので警告にとどめる
- 行番号は、利用者がExcelで探せるように「ファイル上の行(見出しが1行目)」で表示する
- ファイル選択の `input` は、選んだあとに値を空に戻す。そうしないと、同じファイルを選び直したときに反応しない
- 画面のヘッダーのように、ログイン情報を読む部分はServer Componentに、ファイル選択のように操作に反応する部分はClient Component(`"use client"`)に分けた

## Step 6:取り込み(一括insert、置き換え、取り込み履歴)

### やったこと
- `supabase/step6_import.sql` をSQL Editorで実行した。`uploads` に列(`original_row_count`・`original_total_amount`・`uploader_email`)を追加し、関数 `preview_replacement`(置き換えの事前確認)と `commit_upload`(取り込みの確定)を作った
- `lib/upload/importSales.ts` を作った。`uploads` に `pending` の行を作り、明細を5,000行ずつ4本並べて `sales` に送り、最後に `commit_upload` で確定する。失敗したら送りかけた行を消す
- 確認画面に「置き換えの確認」(置き換わる既存データの件数・金額)と、同じファイルを取り込んだことがあるかの表示を追加した。取り込み中は進捗バーを出す
- `/uploads`(取り込み履歴)を作った。状態は「有効／一部置換／置換済み／取り込み中」で、確認してから履歴ごと削除できる
- サンプル → 置き換え用 → 置き換え用(2回目)の順に取り込み、全体の合計が2,502,438円になること、9月以前の数字が変わらないことを確認した
- 10万行版を取り込んだ。取り込み時間は6.5秒だった

### 学んだこと
- 取り込み中の行は `pending` にして、集計には入れない。全件送り終えてから、旧データの削除と有効化を `commit_upload` の中の1つのトランザクションで行う。途中で失敗しても全部取り消されるので、集計が中途半端な状態にならない
- 送った行が欠けていないかを、件数と合計金額で確かめてから確定する。通信の途中で一部の行が失敗しても、そのまま確定されることはない
- `pg_advisory_xact_lock` で、2つの取り込みが同時に確定しないよう順番待ちにした
- 置き換えで行が減った取り込みは、件数・金額を「残っている分」に更新し、取り込み時の値は `original_*` に残した(案A)。こうすると、履歴の合計とダッシュボードの合計が常に一致する。全部の行が置き換わった取り込みは「置換済み」になる
- 関数は作った時点で、誰でも実行できる状態になる。`revoke` で `public`・`anon` から外し、`grant` でログイン済み(`authenticated`)にだけ実行を許可した
- `auth.users` は画面から直接読めないので、取り込んだ人のメールアドレスは、取り込み時に `auth.jwt()` から `uploads` に保存した
- ファイルの中身からSHA-256のハッシュ(指紋)を作ると、ファイル名が違っても同じファイルかどうかを見分けられる
- SQLは、本番のSupabaseで試す前に、Node.jsの中でPostgreSQLを動かせるPGliteで、置き換えのシナリオを確かめた
- 取り込みの6.5秒は、達成基準「取り込み完了から集計の表示まで5秒以内」の対象外。ただし「CSVを選んでから表示まで」と受け取られる可能性もあるので、Step10までに測り方を決める

## Step 7:集計RPC、突合テスト

### やったこと
- `supabase/step7_aggregate.sql` をSQL Editorで実行し、集計用の関数を作った。KPI(`get_kpi_summary`)・月次推移(`get_monthly_sales`)・商品別(`get_product_sales`)の3つと、共通の部品(`filtered_sales`・`yoy_pct`)
- Step2で実行したSQLを `supabase/step2_schema.sql` として残した
- Vitestで突合テストを2種類作った。手元のPGliteで取り込み → 置き換え → 履歴の削除と状態を変えながら試すもの(24件)と、本番のSupabaseの10万行で試すもの(8件)
- 8通りの絞り込み(すべて、全24か月、1か月、年をまたぐ2か月、カテゴリ1つ、担当者2人、カテゴリ2つ×担当者1人、該当なし)で、32件すべてが正解データと1円単位で一致した

### 学んだこと
- 3つの関数の絞り込み条件は、共通の関数 `filtered_sales` にまとめた。条件の書き方が関数ごとにずれると、KPIと表の数字が合わなくなるため
- 期間は「開始月の1日以上、終了月の翌月1日より前」で指定する。「終了月の末日以下」と書くと、日付と時刻の扱いでずれやすい
- 前年同期の行は、1年後の月に読み替えて当年の月と並べた。こうすると、月次推移で当年と前年同月を同じ行で返せる
- 売上のない月も0として返す(`generate_series` で月の一覧を作ってからつなぐ)。グラフの横軸が欠けないようにするため
- 前年比は、前年同期が0のときは計算できないので null(画面では「—」)にする
- テストの正解は、PostgreSQLの `round` と同じ「0から遠い方へ四捨五入」で計算した。JavaScriptの `Math.round` は、マイナスの値で四捨五入の向きが違うので、整数(BigInt)だけで計算した
- わざとバグ(期間の終わりを1日多く含める)を入れてテストを流し、失敗することを確かめた。テストが間違いを見つけられるかも確認しておく
- 最新のVitest(5系)は `@types/node` の22系以上が必要だった。create-next-app が入れる20系のままだと、インストールでエラーになる
- tsconfig の target が ES2017 なので、`1000n` のようなBigIntの書き方は使えず、`BigInt(1000)` と書いた
- テストのデータ投入に `.env.local` のテスト用ユーザーを使った。`.env.local` はGitに上がらないので、パスワードを書いてもよい

### つまずいた点と解決方法
- **症状**:本番のSupabaseのテストだけ、`AuthApiError: Invalid login credentials` で止まった。アプリの画面では同じユーザーでログインできていた
- **原因**:パスワードに `#` が入っていた。`.env` ファイルでは、`#` から後ろはコメントとして扱われるため、パスワードが途中で切れて読み込まれていた
- **解決**:値全体を `"` で囲んだ。`$` も「別の変数を埋め込む書き方」として扱われるので、使う場合は前に `\` を付ける

## Step 8:ダッシュボード画面(KPI・月次推移・商品別)

### やったこと
- `supabase/step8_options.sql` を実行し、関数 `get_filter_options` を作った。有効なデータの最初の月・最後の月・カテゴリ一覧・担当者一覧を返す
- Rechartsを入れ、ダッシュボードを作った。KPIカード(売上合計・前年同期比)、月次推移の折れ線(当年=実線、前年同月=点線)、商品別の表
- 初期表示の期間を、データの最後の月から直近12か月(2025/11〜2026/10)にした
- データがないときの案内と、読み込みに失敗したときの「再読み込み」ボタンを付けた
- 10万行のデータで、売上合計 ¥139,757,614・前年同期比 ▲9.4%・商品別22商品となり、正解データから計算した値と一致することを確認した
- ビルドエラー(下記)を、データを読む部分を `<Suspense>` で囲んで解消した

### 学んだこと
- 3つの集計関数は `Promise.all` で同時に呼ぶ。順番に呼ぶより待ち時間が短くなる
- RPCから返る数値は、型が文字列のこともあるので `Number()` で数値にそろえてから使う
- グラフ(Recharts)はブラウザで動く部品なので Client Component にし、データの取得はサーバー側(Server Component)で行って、結果だけを渡した
- 吹き出し(Tooltip)の中身は、自分で作った部品を `content` に渡すと自由に作れる
- Next.js 16では、create-next-app の初期設定で `cacheComponents` が有効になっている。この設定では、ページの外枠をビルド時に先に作り、Cookieなど「リクエストのたびに変わる値」を読む部分は `<Suspense>` で囲んであとから流し込む
- `<Suspense>` の `fallback` に仮の表示(スケルトン)を置くと、外枠がすぐに出て、データの部分は読み込み中であることが伝わる
- `try/catch` の中でCookieを読むと、Next.jsが内部で投げる合図まで受け止めてしまう。`catch` の最初で `unstable_rethrow(e)` を呼び、Next.jsの合図は投げ直す
- `AGENTS.md` に「このバージョンのNext.jsは知識と違う。`node_modules/next/dist/docs/` を読むこと」とあった。新しいバージョンでは、インストールされたドキュメントで確認するのが確実

### つまずいた点と解決方法
- **症状**:`npm run build` が、`During prerendering, cookies() rejects when the prerender is complete` と `Next.js encountered uncached or runtime data during prerendering` で失敗した(`npm run dev` では問題なく表示できていた)
- **原因**:`cacheComponents: true` が有効で、ビルド時にページを事前に作ろうとした。そのとき、`<Suspense>` で囲んでいない場所でCookieを読んでいた(ヘッダーのメールアドレス、ダッシュボードと取り込み履歴のデータ取得)
- **解決**:Cookieを読む部分を別の部品に分けて `<Suspense>` で囲んだ。あわせて、読み込み失敗のための `try/catch` に `unstable_rethrow` を入れた。ビルド結果で `/`・`/upload`・`/uploads` が「◐(Partial Prerender)」になった

## Step 9:絞り込み、棒グラフ⇄折れ線の切替

### やったこと
- `lib/dashboard/params.ts` に、URLのパラメーターと条件の変換、チップの選び方のルールをまとめた
- 絞り込み(期間・カテゴリ・担当者・条件をリセット)を `FilterBar.tsx` に作った。条件はURL(`?from=2025-11&cat=食品&rep=田中`)に入れ、変えるとサーバーで集計を取り直す
- 月次推移に「棒グラフ／折れ線」の切替を付けた。棒グラフでは当年が棒、前年同月が点線の折れ線。切替はURLの `chart` だけを書き換える
- 絞り込みのルールのテストを12件追加した。全体で44件のテストが通った
- 画面で、食品で絞り込むと ¥38,266,610・▲9.9% になるなど、正解データと一致することを確認した。リロードしても条件とグラフの種類が残ることも確認した

### 学んだこと
- 条件をURLに入れると、リロードしても、URLを共有しても同じ画面を再現できる(No.06と同じ考え方)
- URLのパラメーターは、利用者が書き換えられる「外からの入力」。存在しない月やカテゴリは無視し、範囲外の月は端に寄せ、開始月と終了月が逆なら入れ替えた
- `cacheComponents` では、`searchParams` もCookieと同じ「リクエストごとに変わる値」。ページでは `await` せず、`<Suspense>` の中の部品に渡してから読む
- 条件の変更は `router.push` を `useTransition` の中で呼ぶ。集計を取り直す間も前の画面が残り、`isPending` で「更新中…」を出せる
- グラフの切替のように、サーバーで取り直す必要がない変更は `window.history.replaceState` でURLだけを書き換える。Next.jsのルーターと連動するので、ほかの部品の動きも壊れない
- 棒と折れ線を同じグラフに描くには、Rechartsの `ComposedChart` を使う
- チップの選び方のようなルールは、画面から切り離した関数にすると、画面を開かずにテストで確かめられる
- Next.jsの `searchParams` は、値が1つなら文字列、同じ名前が複数あるときだけ配列になる

### つまずいた点と解決方法
- **症状**:絞り込みのテストを実行すると、`Cannot find package '@/lib/dashboard/period'` で止まった
- **原因**:`@/` はNext.jsが「プロジェクト直下」と解釈する書き方で、Vitestはそれを知らなかった
- **解決**:`vitest.config.mts` の `resolve.alias` に、`@` がプロジェクト直下を指すことを追記した

## Step 10:性能の計測と改善

### やったこと
- 計測の仕組みを作った。開始の時刻をブラウザ(sessionStorage)に記録し、ダッシュボードの集計が画面に出た時点で経過時間を右下に表示する
- 本番モード(`npm run build` → `npm start`)で、10万行版を3回取り込んで測った。取り込み完了から表示まで1.07〜1.48秒、絞り込みの変更から表示まで0.57〜0.95秒で、目標(5秒・1秒)を満たした。取り込み時間(参考値)は5.60〜8.19秒だった
- 基準を満たしたので、性能の改善はしなかった
- 計測の表示は、開発中か `NEXT_PUBLIC_SHOW_PERF=true` のときだけ出るようにした(案A)
- `.env.example` に、テスト用ユーザーと計測の表示の項目を追記した

### 学んだこと
- 性能を測る前に「どこからどこまでを測るか」を決める。今回は、完了画面を人が見ている時間は含めず、ボタンを押してから集計が画面に出るまでとした
- 開発用サーバーは、ページを開くたびにコードを組み立てるので遅い。性能は本番モードで測る
- 1回目が一番遅いのは、起動直後でサーバーやデータベースの準備(接続やキャッシュ)ができていないため。計測は複数回行い、範囲で記録する
- 集計がブラウザに届いた時点ではなく、画面に描かれた時点で測るため、`requestAnimationFrame` を2回重ねてから時間を取った
- ページを移動しても計測を続けられるよう、開始の時刻は `sessionStorage` に保存した。古い記録で誤った時間が出ないよう、1分より古いものは使わない
- `process.env.NODE_ENV` は、`npm run dev` では `development`、ビルドしたものでは `production` になる。`NEXT_PUBLIC_` で始まる環境変数は、ブラウザ側のコードでも読める
- 集計をデータベース側(RPC)で行い、画面には集計済みの数十行だけを返す設計にしたことで、10万行でも表示は1秒台に収まった
- PowerShellとコマンドプロンプトは別物。`PS C:\...>` で始まるのがPowerShell。コマンドプロンプトで `powershell` と入れると切り替えられる

### つまずいた点と解決方法
- **症状**:PCの環境を調べるコマンドが、「.Name の使い方が誤っています」などのエラーになった
- **原因**:PowerShell用のコマンドを、コマンドプロンプトで実行していた
- **解決**:コマンドプロンプトで `powershell` と入力してPowerShellに切り替え、実行し直した

### やったこと

- スマホの幅(Chromeの開発者ツール)で、絞り込み・グラフの切替・商品別の表を確認した
- READMEを仕上げ、デモ画像(`docs/images/demo.png`)を入れた。画像には個人のメールアドレスが写らないよう、`demo@example.com` のユーザーで撮影した

### 学んだこと
- 期限切れと「ただログインしていない」を見分けるには、ログイン情報のCookie(`sb-…-auth-token`)が残っているかを見ればよい
- `cacheComponents` を有効にしたNext.jsでは、`Date.now()` のように時刻で結果が変わる処理を、事前に作るページの中で使えない。`await io()` を先に呼ぶと、その処理はリクエストのたびに実行するものとして扱われる
- `NEXT_PUBLIC_` で始まる環境変数は、ビルドのときにコードへ埋め込まれる。そのため、Vercelで環境変数を追加・変更したら、もう一度デプロイしないと反映されない
- Vercelの環境変数は、Production(本番)、Preview(お試し)、Development(手元)ごとに設定する。手元の開発は `.env.local` を使うので、Developmentは不要だった
- READMEには、本番の公開URLや、キーなどの秘密情報を書かない。環境変数は名前だけを書く

### つまずいた点と解決方法
- **症状**:開発中の画面に「Date.now() while prerendering」というエラーが出た
- **原因**:Supabaseのライブラリが内部で `Date.now()` を使っていて、事前に作るページの中で時刻を読んでいた
- **解決**:`lib/supabase/server.ts` の `createClient` で、`cookies()` のあとに `await io()` を呼ぶようにした

- **症状**:Vercelへのデプロイが失敗し、「No Production Deployment」と表示された。「Redeploy」も見つからなかった
- **原因**:環境変数(SupabaseのURLとキー)を設定せずにデプロイしたため、ビルドに失敗した。成功した本番のデプロイが1件もないため、Redeployする対象がなかった
- **解決**:Settings → Environment Variables に2つの値を設定し(Production and Preview)、Deploymentsの「⋯」→「Create Deployment」から `main` を指定して、新しくデプロイした

- **症状**:環境変数を登録するとき、`NEXT_PUBLIC_` のキーについてVercelが警告を出した
- **原因**:`NEXT_PUBLIC_` で始まる値はブラウザに公開されるため、秘密の値が混ざっていないかを確かめる警告だった
- **解決**:値が `sb_publishable_` で始まる、公開してよいキーであることを確かめてから「Mark as Safe」を押した
